트러블슈팅 1 · 대용량 프레임 지연

Point Cloud 데이터는 프레임 크기가 크고 연속 송수신이 필요해 네트워크 지연이 누적됐습니다. 서버에서 image frame은 즉시 중계하고 depth frame만 CUDA 처리 대상으로 분리했으며, 클라이언트의 depth 전송 주기를 조정해 전송량을 줄였습니다.

트러블슈팅 2 · 처리 병목

CPU에서 모든 픽셀을 보간하면 depth frame 처리 시간이 커져 수신·전송 흐름까지 밀릴 수 있었습니다. depth buffer를 uint16 배열로 변환한 뒤 CUDA kernel로 640x480 데이터를 1280x960으로 확장해 서버 처리 병목을 줄였습니다.

트러블슈팅 3 · 바이너리 스트림 경계

TCP는 메시지 경계를 보장하지 않기 때문에 프레임 단위로 어디까지 읽어야 하는지 명확한 규칙이 필요했습니다. 8바이트 length와 1바이트 type header를 먼저 읽고, length만큼 반복 recv/send하는 방식으로 depth와 JPEG payload를 안정적으로 분리했습니다.

성과

전송 지연을 600ms에서 130ms로 줄여 약 4.6배 개선했고, 연구 결과를 논문과 수상 성과로 연결했습니다.

공연 정보 확인, 로그인, 좌석 선택, 티켓팅, 호스트 공연 관리까지 이어지는 예약 서비스 흐름을 React와 Firebase 기반으로 구현했습니다.

면접 포인트
